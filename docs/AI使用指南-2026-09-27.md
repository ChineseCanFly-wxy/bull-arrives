# Bull Arrives：AI 解读与 Claude Code 使用指南

本版使用本机已安装并登录的 Claude Code。进入任意股票的「个股技术分析」→「AI 研究助手」。先看股票名称、代码、数据时点和量化评分，再选择下面的入口。AI 只解释冻结快照；行情过期时重新打开分析。模型的「主观确定性」不是股价上涨概率。

## 四种用法

| 想做什么 | 点击哪里 | 怎样看进度 | 结果在哪里 |
| --- | --- | --- | --- |
| 问一个关于当前快照的问题 | 「围绕当前快照提问」→「针对问题解读」 | 「当前快照的调用记录」会显示任务、运行时间、进程和实际输入 | 本卡片下方的「AI 解读」；这是单轮问答，下一问会发起新任务；结束后可从记录打开该次 Claude 终端 |
| 直接生成结构化解读 | 「生成 Agent 解读」 | 同上 | 下方的结论、支持因素、风险、证据和失效条件；失败时仍保留量化分析；可从调用记录打开 Claude 终端 |
| 自动进行多角色研判 | 「自动多角色研判（分阶段）」 | 第一轮技术、多方、空方并发；第二轮多空并发；最后风控收口。进度区同时列出正在运行的角色 | 下方各角色观点与风控结论；最多六次调用，角色借由前一轮结果交换观点；每一轮可分别打开 Claude 终端 |
| 一边看 Claude 工作一边追问 | 「新建应用内会话」或「打开 Claude Code 终端」 | 应用内会话显示回复和工具名；终端显示完整 Claude Code 界面 | 应用内会话直接显示文字；外部终端需在任务结束后点「导入结果」才成为校验过的解读 |

## 可见终端与真正的 Agent Team

- 「打开 Claude Code 终端」是普通交互会话。正常的 Claude Code 设置、命令、skills 和 MCP 会加载；模型与工具权限由 Claude Code 自身管理。启动时它会读取本次 `input.json` 与 `workflow.md`，先说明数据时点，然后等待你提问。你可以在终端直接追问。
- 终端以固定的应用任务根目录为工作区，每次分析文件放在独立编号的子目录。Claude Code 首次询问是否信任该工作区时，请核对终端显示的路径是否为应用数据目录；确认后同一根目录内的新任务不必逐个重新确认。不要跳过未经核对的信任提示。
- 「打开原生 Agent Team 终端」仅为这个终端启用 Claude Code 的实验性 Agent Team。启动指令要求技术、多方、空方三个队友并行研究、相互发送消息，由主会话做风控综合。团队会尝试把阶段摘要写入 `progress.md`，展开应用中的任务状态可以看；实时工具执行与队友聊天仍以终端为准。
- Team 终端仅对 `technical`、`bull`、`bear` 三个具名角色的 `Agent` 调用应用任务级 `PreToolUse` 参数修正：移除模型自行添加的 `isolation` 与旧式 `team_name`，保留角色提示和其他参数。普通 Claude 终端不加载这个修正；Team 是否实际组成仍以 Claude Code 团队成员记录为准。
- 在任务的「查看状态」中，应用会读取 Claude Code 当前的团队成员记录：出现 `technical`、`bull`、`bear` 才表示这些原生队友确实加入。只看到「终端窗口运行中」表示终端脚本已运行，不能证明原生团队形成。Claude Code 自行启动的普通子代理不会被算作队友。
- 每个终端标题显示股票、用途和任务编号。普通终端是当前快照的问答；Team 主终端是风控负责人。队友 `technical` 检查趋势与指标，`bull` 寻找支持证据，`bear` 寻找风险与反证；开场提示和任务状态中也有角色说明。
- 在 Windows Terminal 中，原生团队使用 Claude Code 的**单终端进程内视图**。在队友列表用上下方向键选人、回车查看其对话并直接发送消息；`Ctrl+T` 查看任务列表。你可以同时打开多个任务终端，但它们是彼此独立的团队，不能把不同团队误认为同一个共享消息组。真正的分屏队友终端需要 tmux 或 iTerm2，Windows 环境默认不提供这种多窗分屏；一个终端里的队友仍能互相发消息。
- 原生团队比单轮分析消耗更多模型用量。外部交互终端不受应用「单次后台预算」和 180 秒后台超时控制；具体额度与权限提示以 Claude Code 为准。

## 终端做完后怎样导入

1. 在终端确认 Claude 已完成分析。如果没有生成 `response.json`，明确告诉它：「请根据当前目录 `schema.json` 生成可导入的 `response.json`，只使用 `input.json` 中的证据字段。`summary` 和每条 `claims.text` 不要写阿拉伯数字，价格、日期和带数字的指标名改用文字描述，实际数值交给证据卡显示。」团队任务也一样。
2. 回到应用，在该股票分析中的任务列表展开「查看状态」。这里显示终端是否仍在运行、团队写入的进度、结果文件是否存在；文件存在不代表内容已通过校验。
3. 点击该任务的「导入结果」。应用会核对快照指纹、数据时点、输出结构和证据字段。当前快照显示为当前解读，历史快照仅供回顾。校验失败按错误提示回终端修正，再点一次导入。
   Team 任务导入后，最终结论上方会直接展示 `progress.md` 的负责人讨论摘要，包括角色分工、交叉质疑和风控取舍；该摘要是 Claude Code 写的过程记录，未经过与最终 `response.json` 相同的证据校验，原始队友对话仍在终端查看。相同快照下，Team 与单个 Agent 得出相同最终方向并不奇怪，主要区别在推理过程和相互质疑。
4. 下次想继续同一任务，点击「终端继续」。关闭终端后才清理任务文件；清理不会删除数据库中的量化快照。

## 「发了话后没反应」时检查

- **应用内连续对话**：发送后看输入框上方的「本轮正在运行 / 未运行」和消息区。工具调用只显示名称，不显示参数和工具输出。每轮最多 300 秒；需要人工批准的工具操作可改用外部可见终端。
- **快照问答**：它不是聊天框，而是一次后台结构化分析。看到「执行中」时可在调用记录中检查进程与耗时；结束后向下看 AI 解读卡。若报超时、权限或额度错误，先去「设置 → 智能」做「测试连接」，再用终端确认 Claude Code 可正常工作。
- **后台任务的终端**：任务结束后，在「当前快照的调用记录」里点击该次的「打开 Claude 终端查看」，会恢复对应的 Claude Code 会话，供你看原始过程并继续提问。旧版调用没有可恢复会话；同一快照的缓存复用没有新进程。终端里继续聊天不会更改已经保存的结构化结果。
- **外部终端**：应用会等待任务目录出现终端启动状态，八秒内没有确认会直接报错并保留任务文件。状态显示「终端窗口运行中」只确认窗口里的 PowerShell 仍在运行；Claude Code 可能仍在等待首次工作区信任确认。请核对终端提示和设置中的 Claude Code 路径。
- **自动多角色**：第一轮最多三个进程并发，第二轮两个并发；各阶段结束后才开始下一阶段。应用的“中止”会停止正在执行的并发调用。若要队友直接互通消息，点击「打开原生 Agent Team 终端」。

## 设置与权限

### 资讯通知：直接通知 / 混合模式

在「设置 → 行情提醒 → 全市场重要资讯」或右下角「资讯与提醒」中开启采集，并选择方式：

- **全部直接通知（默认）**：重要事件规则命中后推送采集原文，不调用 AI。
- **混合模式**：全部重要资讯先推送原文；重大事件、自选股相关消息或命中自定义关注词时，才在每日名额内调用本机 Claude Code。完成后更新同一条记录，并追加一条 AI 解读提醒；名额用完、AI 关闭或调用失败时仍可查看原文。AI 解读会列出事实、观点、相关行业、来源代码及原文明确出现的公司名称、利好/利空方向及影响程度。行业来自推断时标为“推测”；没有可靠关联时明确未确认。原文只有公告标题时不能冒充读取过公告全文。

自动名额默认每天 **3 条**，可在「设置 → 提醒」设为 **0–20 条**；0 表示只允许手动解读。关注词最多 10 个，用逗号隔开。每条已保存的资讯都可以在「资讯与提醒」中手动点击「手动 AI 解读」，不消耗自动名额。自动名额在调用前登记，失败也计入，避免重启或并发重复花费。`$10` 是 Claude Code 的**单次调用上限**，不是每天最多花 $10，也不是每条固定收费。旧版“全部 AI 解读”设置在升级时迁移为混合模式。

隔离原生验收（混合模式）：在独立便携目录中通过真实界面切换模式、保存关注词「楚天龙」和每日上限 1 条，快讯与公告均建立首次水位。重放两条当前来源中的资讯：包钢股份事件保持直接通知，楚天龙事件先通知原文、再由本机 Claude Code 解读并更新原档案；档案总数始终为 2，自动用量为 1。手动点击包钢股份的「手动 AI 解读」后，该档案得到观点与行业信息，自动用量仍为 1。两条均非自选，说明混合模式不依赖自选股。测试程序已关闭；现用安装目录及用户数据库未改动。

资讯包含东方财富财经快讯、上市公司快讯和全市场公告，不依赖自选股列表。自选股相关事件用「★自选」标记。全天采集，白天约每分钟、深夜约每五分钟检查。原先只有数量统计的盘前、盘后和夜间卡片已移除，旧卡片在启动时从资讯档案清理。

「资讯与提醒 → 每日简报」在交易日北京时间 09:10 后生成盘前简报、15:15 后生成盘后简报；只有本机已保存的记录才会进入简报，没有记录时不会生成空卡片。盘前从上一个可确认交易日的 15:15 起汇总已接收的全市场重要资讯和自选股相关事件；盘后从当日 09:10 起汇总资讯及价格/风险提醒。每份展示最近 5 条重大事件、5 条其他自选股相关事件、3 条其他重要资讯和 10 条提醒，未展示的资讯仍可在市场资讯中查阅。简报保存生成时的标题、摘录和提醒，重启后可回看最近 60 份；原始资讯档案仍只保留最近 500 条，过期后不能再对该条发起手动 AI 解读。简报本身不自动调用 Claude；打开简报可对尚在档案中的单条资讯按需解读。未运行或关闭资讯采集的时段无法补齐市场资讯，窗口显示的是本机接收时间，不是事件在市场发生的时间。

每日简报验收：Rust 全量测试 281 项通过、25 项按既有条件跳过，新增检查覆盖跨休市日的盘前窗口与简报重启回看；前端构建及隔离组件检查通过。独立便携原生窗口使用合成记录，验证真实 Tauri IPC 读取已保存的资讯/提醒、简报页面的手动 AI 入口和滚动列表；未调用 Claude，未修改现用安装或用户数据。生成时间调度由源码测试与窗口规则验证，未等待真实交易日定时点进行实地验收。

规则保留风险、重大事项、业绩预告/快报、资本事件、重大合同与政策行业事件，过滤普通决议、章程、投资者关系记录、回购进展等常规内容。没有 A 股代码的财经快讯还需有明确的 A 股、国内政策或央企语境，避免体育等无关报道仅凭“处罚”误入。规则筛选有覆盖边界，AI 判断也不代表后续股价必然变化。快讯每类取最新一百条，公告取最新三页，每页一百条；长时间离线或极密集发布时不能保证补齐所有消息。

首次开启、重新开启及旧版升级首轮只建立当前水位，不集中补推历史消息。资讯保留最近五百条，重启可查看采集原文与解读。

验证：规则筛选、无自选全市场处理、首次水位/去重、通知字段/自选标记与记录持久化测试通过；两类在线快讯和全市场公告通过真实请求；新版结构化解读通过本机 Claude Code 实跑。`node scripts/check-news-ui.mjs` 使用真实 Vue 组件和隔离无界面浏览器验证模式保存请求、完整解读展示、原文转义、提醒记录定位与长消息的“查看”按钮，IPC 使用测试响应，不能当作原生 Tauri / Windows 通知验证。

桌面提醒仅展示标题和正文预览，点击“查看”会打开并定位本次提醒中的完整记录。资讯先写入持久化档案再广播事件，避免已打开的资讯列表刷新时漏掉刚到的消息。

隔离原生验收：将构建 exe 复制到独立临时便携目录，其数据库和日志均位于该目录。实际点击「直接通知 / AI 解读」后，经 Tauri IPC 与 SQLite 验证模式保存；打开采集后快讯、全市场公告均建立首次水位，未补推旧消息。测试通知和一条真实来源的非自选「楚天龙中标数字人民币硬钱包管理系统项目」分别通过 Windows 通知调用（系统返回 `accepted`，应用桌面提醒返回 `queued`）；直接通知与 AI 解读两次消息都进入应用内提醒和持久化档案。AI 解读包含事实、观点、利好方向、影响不确定、数字人民币行业、楚天龙及 `003040`，并保留原文依据。Windows `accepted` 仅证明系统受理，不能证明用户实际看见横幅；本验收没有摄取屏幕证明横幅可见。未覆盖现用安装目录或用户数据库。

「设置 → 智能」中，Claude Code 路径留空会自动检测。后台单次预算最低、默认都是 **$10**，最高 **$50**；这是单次调用上限，不是账户余额或实际花费。后台超时默认 **180 秒**，最多 300 秒。自动多角色最多进行六次独立调用，所以总耗时和实际用量可能高于一次单股解读。终端沿用你日常 Claude Code 的模型与登录状态，应用不保存认证信息。

后台任务不再启用 Claude Code 的 restricted/safe 模式，不屏蔽用户 skills、MCP 或普通工具。应用只预先放行任务目录里必要的读写操作；其他需要人工批准的工具在无交互的后台调用里可能不能执行。请用可见终端完成需要人工批准的操作。应用始终校验导入的结构化结果，终端自由对话不会直接写入预测或交易账本。

参考：[Claude Code CLI 命令与权限参数](https://code.claude.com/docs/en/cli-reference)、[原生 Agent Team 的启用、消息和 Windows 显示限制](https://code.claude.com/docs/en/agent-teams)。

本机验证（Claude Code 2.1.269）：Windows Terminal 可启动 UTF-8 脚本，普通 Claude 交互终端能读取中文提示并回复。原有 Team 任务里模型自动给 Agent 添加 `isolation=remote`，只形成普通子代理；修正后真实交互式 CLI 烟测确认，模型虽仍发出该参数，任务级 hook 将其移除，Claude Code 随即建立包含负责人、`technical` 和 `bull` 的原生 Team 成员记录。此前普通具名代理通过 `SendMessage` 直接往返成功，修正后的原生团队消息和应用按钮仍需在安装版中点击验收。请以应用任务状态中的实际团队成员和终端队友面板为准。
