## 二、增强前 AI 到底在做什么

1. 单股：把程序算好的指标交给 Claude，返回四选一方向、证据字段、主观确定性、失效条件。没有自由解释段落，因此看起来像在重复规则。
2. 团队：技术、多方、空方三个独立任务各发言一次，风控看三人的发言。没有真正的多空反驳。
3. 资讯：对规则命中的新闻生成摘要和情绪；不会自主搜集新资料。
4. 动态筛选：按市场汇总给参数建议，代码做护栏处理。未有自动应用或完整效果评估闭环。

评分、指标、止损止盈、回测、提醒本来就由 Rust 代码计算，不是 AI 的能力。模型主观确定性也不是上涨概率。

## 三、为什么没看到 Claude 窗口，为什么装的 skills 没生效

应用用隐藏 Windows Job/launcher 执行 `claude -p`。`CREATE_NO_WINDOW` 隐藏窗口；`--no-session-persistence` 不留可继续的交互会话；文件传入/传回数据。

`--safe-mode`、`--disable-slash-commands`、`--strict-mcp-config` 和空 `empty-mcp.json` 意味着本机自定义 skills、MCP、hooks 并未参与。允许的内置工具是 Read/Write，结果写入限于 response.json。模型和认证仍沿用 Claude 自身配置。

因此当前是“用 Claude Code 执行受限研究任务”，而不是打开一个全能 Claude 工作台。将终端窗口显示出来只改变可见性，不能补齐数据和能力。

## 四、本轮实际增强

- **方法文件化**：应用提示词拆分为 `src-tauri/prompts/*.md`，包含公共约束、单股、技术、多方、空方、风控、资讯、筛选和连接测试。程序通过 `--append-system-prompt-file workflow.md` 使用对应方法，文件内容与方法指纹可在界面查阅。
- **补齐行情上下文**：把同次量化分析已获取的最近最多 60 根前复权日 K 加入冻结快照，不重复请求网络；条数、区间与来源在预览中显示，K 线内容参与指纹校验，旧快照保持兼容。
- **解释变成证据卡**：单股输出中文 summary 和 2–6 条判断，分支持、风险、观察；每条绑定真实字段、数值、来源、时间。缺风险条目、引用不存在的字段、自然语言直接输出新数字时拒绝结果。语义仍是模型解释，不能把结构校验说成已证明解释正确。
- **快照提问**：可围绕当前快照提交最多 500 字的问题，问题仅作为任务数据；相同问题与数据可缓存。不是连续会话聊天，也不会访问额外文件。
- **三阶段研判**：技术/多方/空方独立 → 多空各读取同一份首轮观点作回应 → 风控综合。共最多六次真实调用、单并发。每次预算上限 $0.20，合计上限 $1.20；实际计费以服务商为准。
- **过程可见**：当前角色、阶段、后台任务 PID、实际耗时、单次超时可查，不伪造模型内部思考流。
- **真实调用记录**：本地保存最近 100 次输入、应用提示词、结构约束、耗时、调用状态；界面按当前快照显示最近 20 次，点击查看实际发出的内容。记录是调用轨迹，不表示业务校验必定通过；缓存不会增加调用记录。
- **版本与兼容性**：方法内容纳入缓存键；校验旧快照时使用快照本身的版本，避免更新提示词后旧数据再次指纹失败。
- **耗时修正**：多角色去除隐蔽的 30 秒硬上限，遵从用户配置的单次超时。资讯/动态筛选仍保留更短的后台上限。

方法文件不是已安装到 Claude 的原生 Skill，也不是热加载的外部插件。它们随应用构建打包，修改源码后需重新构建。这样先让当前能力可读、可检查，再单独设计真正的受控扩展，避免声称“装了 Skill 就全会了”。

## 六、仍需实施的后续能力（不记为本轮完成）

1. **数据覆盖**：在本轮已接入的逐根日 K 之外，加入公告/财报摘要、板块资金数据和盘口。缺失字段需显式标记；有数据才新增对应分析师。
2. **受控扩展**：在设置中注册白名单 Skill/MCP，预览它将获得的数据和权限，按角色派发；保持默认受限模式。与全局 Claude 配置隔离，不直接全量启用。
3. **真实预测结算**：后台按交易日结算、按任务周期对齐、展示校准看板。谨慎意见不宜简单计为下跌预测；未校准确定性不作为交易胜率。
4. **策略研究闭环**：先补齐时点股票池、公司行为、组合账本和前向证据，再让 AI 提出结构化候选并登记验证；不能直接绕过当前 blocked 门禁。

本轮不把“自动找出好策略”包装成已实现功能，不因增加角色数量就宣称准确率提升。
