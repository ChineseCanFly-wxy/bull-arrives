# AI 功能排查与修复（2026-09-19）

## 已确认根因

用户界面报错为“Agent 冻结快照指纹校验失败”。程序在启动 Claude Code 前，会对数据库中保存的量化快照重新计算 SHA-256。`serde_json` 原先没有启用 `float_roundtrip`，部分 f64 在 JSON 序列化、反序列化后不能保持同一数值位模式，再序列化的字节随之变化，导致指纹不一致。

本机已保存快照中的 `-9.007605460051991` 可稳定复现：修复前回归测试失败，启用精确浮点数往返解析后通过。原有仅含简化数值的单股冒烟测试无法捕获此问题，现已加入该数值。仍然保留指纹校验；篡改数据的测试必须继续失败。

## 修改范围

- 开启 serde_json 的 float_roundtrip，保持真实量化数据的快照指纹稳定。
- 自动检测补充用户原生安装位置，避免桌面启动环境中的旧 PATH 漏检。
- 区分“找到安装文件”和“实际连接成功”，新增主动测试连接及 15–300 秒超时设置。
- 恢复运行所需的 HOME、PATH、代理、证书与 Claude 配置目录环境；不读取或落库认证密钥。
- 持续读取 CLI 诊断输出，只在内存保留有界尾部并返回固定分类提示，不把原始输出写入日志、文件或界面。
- 阻止单股与多角色按钮同时发起调用，显示多角色异常；中止后停止后续角色，风控失败不以其他角色充当最终意见。
- 针对快照失败显示重新分析的指引，避免误导用户排查登录与网络。

## 验证方式

默认单元测试覆盖浮点指纹往返、数据篡改、错误分类、输出缓冲上限、安装候选路径和风控失败回退。

`stored_snapshot_fingerprints_match` 是只读手动审计测试，通过环境变量 `BULL_AGENT_SNAPSHOT_DB` 指定已有数据库，逐条检查持久化快照。真实模型测试沿用 ignored 测试，默认单元测试不联网；Windows 模型测试前需构建 `cargo build --bin bull-arrives`。

- 本机已有数据库的 3 条持久化快照全部通过指纹校验，数据库以只读方式打开。
