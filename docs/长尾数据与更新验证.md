## 更新产物与安装形态

仓库使用 Tauri v2 updater、固定公钥和 `createUpdaterArtifacts: true`。2026-09-18 实取最新版本 `v1.5.3` 的 `latest.json`，以下键均有非空 URL 与 minisign 签名：

- Windows：`windows-x86_64-msi`、`windows-x86_64-nsis`，并保留通用回退键。
- macOS：`darwin-aarch64-app`、`darwin-x86_64-app`，均指向 universal `.app.tar.gz`。
- Linux：`linux-x86_64-appimage`、`linux-x86_64-deb`、`linux-x86_64-rpm`，并保留通用 AppImage 回退键。

Tauri updater 会优先按当前 bundle type 选择 `{os}-{arch}-{installer}`，因此 NSIS、MSI、AppImage、deb 和 rpm 不会在已识别安装形态下互相替换。NSIS 首装模式已显式固定为 `currentUser`；updater 的 Windows 安装界面模式为 `passive`。绿色版继续禁止应用内更新。

| 平台/形态 | 构建与更新签名 | 真实安装/更新 | 当前结论 |
|---|---|---|---|
| Windows NSIS currentUser | 已验证 manifest 与产物键 | 未执行跨版本安装 | 设计上无需管理员权限；仍需用旧版到新版验证 UAC、安装目录、卸载项、用户数据和重启版本。 |
| Windows MSI | 已验证 manifest 与产物键 | 未执行跨版本安装 | MSI 可能触发管理员权限；作为独立安装形态保留。 |
| macOS Intel / Apple Silicon | CI 生成 universal updater 包并有 updater 签名 | 当前无 macOS 环境 | 未发现 Apple Developer ID 签名与 notarization 配置，不能宣称 Gatekeeper 验证通过。 |
| Linux AppImage | CI 生成 AppImage 并有 updater 签名 | 当前无 Linux 环境 | 仍需验证原 AppImage 所在目录可写、替换成功及重启版本。 |
| Linux deb / rpm | manifest 有各自 bundle 键 | 当前无 Linux 环境 | 仍需验证包管理器权限、安装与重启；不能用 AppImage 结果代替。 |

Windows Authenticode 与 updater minisign 是两套签名。当前仓库只证明 updater 完整性签名存在，未发现 Authenticode 证书配置，因此不能宣称 SmartScreen 显示受信任发布者。
